기본 환경의 실제 인증 유지도 요청으로 확인했다. `profiles/default-control/`에 별도의 임시 설정·대화 경로를 만들고 SSH 감지 변수를 제거해 기존 OS 키체인 인증을 사용했다. API 키·ADC·게이트웨이 환경은 제거했다. 대조군에는 파일 인증이 실행 전후 모두 없었고, A 로그아웃 전후 및 재로그인 이후의 짧은 모델 요청이 모두 정상 응답했다. 기본 설정·대화 디렉터리에 테스트 대화를 만들지 않았다. 기본 앱의 화면 자체를 검사한 결과와는 구분한다.

초기 실행 경로 검토에서 이 버전의 비대화형 `-p /logout`은 지원되지 않았고, macOS `script`도 실제 TTY 입력이 필요했다. 이때 A 인증은 제거되지 않았으며 기존 환경 변화도 없었다. 실제 TTY 입력으로 `/logout`을 수행한 뒤에만 로그아웃 격리 근거로 인정했다. PTY 화면 원문은 공유 결과에 저장하지 않았다.

사용자가 원래 A 계정으로 공식 재로그인하고 종료한 뒤, **00:18:03~00:18:44 KST**에 후속 검증했다. 새 A 프로세스가 원래 계정·대화를 복원했고 이전과 다른 접근 토큰을 사용했다. B의 인증은 재로그인 구간에도 바뀌지 않았으며 A·B 모두 응답했다. 기본 키체인 대조군도 응답했다. 로그아웃·공식 재로그인·후속 검증 구간의 기존 설정 파일과 키체인 메타데이터는 그대로였다.

당시 상세 근거는 `P6-state.json`과 `verify-P6-1793027924871.json`이었다. 정리 전에 모든 판정 항목을 공유 결과 JSON에 옮겼고, 인증 지문·이메일·토큰 원문은 옮기지 않았다.

## P7 정리와 원본 기준 차이 검토

모든 실험 프로세스가 종료됐음을 확인하고 공유 가능한 단계별 판정·검사 결과를 먼저 저장했다. 원래 P0 기준에 비해 기존 설정 파일의 차이는 없고 키체인 메타데이터 차이가 있었다. 이 차이는 원본을 덮어써 없애지 않았다.

최초로 관찰한 키체인 수정 **10월 26일 22:14:28 KST**는 첫 PoC 로그인보다 앞섰고, 사용자는 기본 앱·CLI도 사용했다고 확인했다. 최종 항목 수정 시각 **23:49:11 KST**도 P5 실행 시작 **23:49:43 KST**보다 앞섰다. P5와 정식 P6의 각 실행 구간 비교에서는 변화가 없었다. P6 시작 전과 최종 정리 준비 시점 사이에도 추가 변경이 없었다. 이 외부 구간의 원본 차이와 실제 실험·정리 중 변경을 구분해 검토했다.

검토 기록은 원본 기준 파일 해시·허용한 차이·원인·현재 체크포인트를 연결했다. 정리 명령은 검토 시점 이후 추가 변화가 있거나 원본 해시가 달라지면 삭제 전에 중단하도록 검증했다. 원본·검토 기록을 임의로 복원하거나 기본 키체인을 교체하지 않았다.

**2026-10-27 00:21:40 KST**에 전용 루트를 삭제했고 삭제 후 비교 결과는 다음과 같았다.

- 원래 P0 기준 대비: 기존 설정 파일 차이 없음, 이미 검토한 키체인 메타데이터 차이 있음.
- 정리 직전 검토 시점 대비: 기존 파일·키체인 모두 추가 변경 없음.
- **00:23:12 KST** 최종 확인: 전용 루트 없음, 해당 루트로 실행된 `agy` 프로세스 0개.

`postCleanupMatchesBaseline`은 기존 차이를 숨기지 않고 `false`로 유지했으며, `postCleanupMatchesReviewedBaseline`은 `true`였다. 공유 결과 JSON에 두 판정과 `changesDuringCleanup`을 모두 보존했다. 임시 프로필의 토큰·원시 로그·비공개 상세 근거는 전용 루트와 함께 삭제했다.

## 비교 범위와 해석의 한계

기존 `~/.gemini/config/`의 설정·훅·MCP 설정, 기본 CLI 설정·설치 식별자·상태 파일, 알려진 인증 파일과 키체인 우회 마커를 비교했다. 키체인은 `gemini` 서비스의 첫 일치 항목에 대해 비밀값을 제외한 메타데이터 다이제스트를 비교했다. 키체인의 모든 인증 항목이나 전체 파일 시스템 쓰기를 추적한 결과는 아니다. 메타데이터가 같다는 사실만으로 독립 OAuth 프로필 전체를 증명하지 않는다.

샌드박스 안에서 `security find-generic-password`는 실제 존재하는 항목을 `absent`로 보고했다. 같은 조회를 실제 사용자 권한에서 실행하자 항목이 관찰됐다. 이 차이를 확인한 뒤 준비용 run 두 개를 실제 P0·P1 근거에서 제외하고, 동일한 사용자 권한으로 새 기준 상태를 수집해 실험했다.

P1이 통과했다는 것은 **빈 경로의 미로그인 상태, SSH 감지 파일 저장소 선택, 프로필 내부 경로 생성과 비교 대상의 무변경**을 확인했다는 의미다. 사용자 로그인 이후 계정·대화·설정 파일의 재접속과 동시 실행 독립성은 P2~P4에서 별도로 확인했다. 자연 갱신과 갱신 후 재접속은 P5에서 확인했다. P6에서는 실제 로그아웃·공식 재로그인과 기존 키체인 인증 대조군의 요청도 확인했다. 기본 앱 UI 전체나 모든 키체인 항목을 검사한 결과로 확대하지 않는다.

## 구현과 도구 검증

`run.mjs`, `lib.mjs`, `verify.mjs`, `logout.mjs`는 전용 루트 생성, 실행 조건 구성, 버전·옵션 검사, 빈 프로필 요청, 실제 TTY 런처, 프로세스 기록, 전후 비교, 단계 기록·무효화, 종료, 잠금 복구와 정리를 구현한다. 자식의 `HOME`이나 사용자 셸 설정은 바꾸지 않는다. 프로세스별 인자·환경을 사용하고 API 키·ADC·게이트웨이 등 경쟁 인증 환경은 제거한다.

`npm test`는 **25개 테스트 통과, 실패 0개**였다. 환경 격리, 경로·권한·심볼릭 링크, 바이너리 교체 감지, 단계 순서, 원시 출력 비밀값 제외, 시간 제한, PID 식별·종료 범위, 미검증 데이터 폐기 보호와 잠금 복구를 검증한다. 런타임 삭제 후 기존 상태를 다시 비교하는 정리 경로도 모의 실행으로 확인했다. 계정 비교의 원문 비노출, 스트리밍 세션의 연속 요청·종료, 만료 전 요청 차단도 모의 데이터로 검증했다. 기본 인증 대조군의 SSH 환경·경로 분리와 원본 기준 차이 검토, 미검토·추가 변경 시 정리 차단도 모의 데이터로 확인했다. 도구 테스트 결과는 실제 OAuth 실험 결과와 구분한다.

## 본 개발 판단

**착수 가능.** 고정한 macOS arm64·Antigravity CLI 1.4.7에서 P0~P7을 모두 통과했다. 두 개인 OAuth 계정의 파일 인증 분리, 재접속, 동시 실행, 자연 갱신, 로그아웃·공식 재로그인 격리와 임시 데이터 정리 근거가 확보됐다.

본 개발에서는 `create`·`list`·`remove`·`doctor`, 프로필 레지스트리와 런처를 범위로 정한다. 미문서화 경로 옵션의 버전별 동작과 SSH 감지 환경이 하위 프로세스에 미치는 영향을 구현·지원 정책에 반영해야 한다. 이번 결과는 다른 CLI 버전, OS, ADC·API 키, 플러그인·MCP 전체 호환성까지 검증한 결과는 아니다.
